# Мой карман — личный финансовый трекер

Учёт доходов и расходов в рублях (₽): быстрый ввод одной строкой, автоопределение категорий с обучением, история с фильтрами, цели, аналитика, бюджет, экспорт и импорт.

## Архитектура

```
Браузер (Next.js 15 + React 19, адаптивный интерфейс)
   │  supabase-js: запросы с токеном пользователя
   ▼
Supabase
   ├─ Auth — вход по почте и паролю
   ├─ REST API (PostgREST) — автоматически сгенерированный backend
   └─ PostgreSQL — данные + Row Level Security
```

Отдельный backend-сервер не нужен: API Supabase и есть backend. Безопасность обеспечивается не кодом сервера, а политиками RLS прямо в базе — каждый запрос выполняется от имени пользователя, и база сама не отдаёт и не даёт менять чужие строки. Это надёжнее самописного API: меньше кода, меньше мест для ошибки, проще поддерживать.

### Как защищены данные

| Риск | Защита |
|---|---|
| Закрыли браузер / обновили страницу | Каждое действие сразу пишется в PostgreSQL; при входе всё загружается из базы. LocalStorage хранит только токен сессии |
| Двойной клик, плохая сеть, повторная отправка | У каждой операции UUID создаётся в форме один раз; повторная отправка с тем же id игнорируется базой (`on conflict do nothing`) |
| Случайно внесли то же самое дважды | Предупреждение «Похоже на дубль», если такая же операция добавлена в последние 3 минуты |
| Повторный импорт файла | JSON и CSV из приложения содержат id → дубли невозможны. CSV из других источников сверяется по дате, сумме, названию и категории |
| Случайное удаление | Мягкое удаление: «Отменить» в уведомлении, кнопка «Вернуть» в истории, корзина в настройках |
| Случайная правка | Триггер пишет старую версию записи в таблицу `transaction_log` при каждом изменении и удалении |
| Ошибки округления | Все расчёты в копейках (целых числах), в базе `numeric(14,2)` |
| Неверные данные | Проверки в базе: сумма > 0, категория из списка, длина текста |
| Чужой доступ | RLS на всех таблицах, анонимный ключ без входа ничего не читает |
| Потеря базы | JSON-копия из приложения + ежедневный автоматический дамп через GitHub Actions (см. ниже) |

### Структура базы (`supabase/schema.sql`)

- `transactions` — операции: тип, название, сумма, категория, дата, комментарий, `deleted_at` для мягкого удаления.
- `goals`, `goal_contributions` — цели и их пополнения (снятие — отрицательная сумма). Накоплено = сумма пополнений.
- `category_rules` — выученные исправления категорий («кофе» → «Развлечения»).
- `user_settings` — начальный остаток, месячный бюджет, дата последней копии.
- `transaction_log` — журнал изменений (только чтение).

## Запуск: 15 минут

Нужно: [Node.js 20+](https://nodejs.org), бесплатный аккаунт [Supabase](https://supabase.com).

**1. Создайте проект в Supabase.** New project → придумайте пароль базы (сохраните его) → регион ближе к вам (например, Frankfurt).

**2. Создайте таблицы.** SQL Editor → New query → вставьте весь `supabase/schema.sql` → Run. Должно быть «Success. No rows returned».

**3. Возьмите ключи.** Кнопка Connect (или Project Settings → API): Project URL и anon public key (либо publishable key). Скопируйте `.env.example` в `.env.local` и вставьте значения:

```
NEXT_PUBLIC_SUPABASE_URL=https://ваш-проект.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=ваш-ключ
```

Это публичный ключ — он и так виден в браузере, данные защищает RLS. Секретный service_role key никуда не вставляйте.

**4. Запустите.**

```bash
npm install
npm run dev
```

Откройте http://localhost:3000, нажмите «Регистрация», подтвердите почту по ссылке из письма и войдите.

**5. Закройте регистрацию для посторонних** (это ваш личный кабинет): Authentication → Sign In / Providers → выключите «Allow new users to sign up». Вход для вас продолжит работать.

## Публикация в интернете

Приложение собирается в статический сайт (папка `out/`), поэтому подойдёт любой хостинг.

**GitHub Pages (используется сейчас):** адрес https://payshanbieva17-boop.github.io/moy-karman/. При каждом изменении в ветке `main` сайт пересобирается автоматически (`.github/workflows/deploy.yml`). Адрес и публичный ключ Supabase прописаны в этом файле. В Supabase → Authentication → URL Configuration указан Site URL этого адреса.

**Vercel / Netlify (по желанию):** импортируйте репозиторий, добавьте переменные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`, папка публикации — `out`. `NEXT_PUBLIC_BASE_PATH` не задавайте: сайт будет в корне домена. Не забудьте добавить новый адрес в Redirect URLs в Supabase.

**На телефоне:** откройте сайт в Safari → «Поделиться» → «На экран „Домой"» (iPhone) или меню → «Добавить на главный экран» (Android).

## Резервное копирование

**Вручную (рекомендуется раз в неделю):** Настройки → «Резервная копия (JSON)». Файл содержит все операции, цели и правила. Восстановление: «Импорт JSON / CSV» — существующие записи не дублируются и не перезаписываются. Приложение напомнит, если копии не было больше недели.

**Автоматически, каждый день:** в репозитории уже есть `.github/workflows/backup.yml`.
1. Supabase → Connect → Session pooler → скопируйте строку подключения и подставьте пароль базы.
2. GitHub → Settings → Secrets and variables → Actions → New repository secret: `SUPABASE_DB_URL` — эта строка; `BACKUP_PASSPHRASE` — придуманный вами пароль для шифрования (сохраните его, без него копию не открыть).
3. Actions → DB backup → Run workflow — проверьте, что первый запуск зелёный.

Копии шифруются (AES-256), поэтому их безопасно хранить даже в открытом репозитории. Хранятся 30 дней в Actions → запуск → Artifacts. Расшифровать: `gpg -d moy-karman-ДАТА.dump.gpg > backup.dump`. Используйте Session pooler, а не Direct connection: прямое подключение работает только по IPv6, а у раннеров GitHub его нет.

Восстановить расшифрованный дамп: `pg_restore --clean --if-exists --no-owner -d "строка_подключения" moy-karman-ДАТА.dump`.

**Важно про бесплатный тариф Supabase:** на момент написания неактивные проекты на Free-тарифе ставятся на паузу примерно через неделю без запросов; данные при этом сохраняются, проект возобновляется кнопкой в панели. При ежедневном использовании это не случается. Встроенные ежедневные бэкапы Supabase есть только на платных тарифах — поэтому в проекте два своих способа копирования. Условия тарифов меняются, проверьте актуальные на supabase.com/pricing.

## Пользование

- **Быстрый ввод** на главной: «Обед 35», «Такси 12,50», «150 аптека», «Кофе 15 вчера». Сумма — последнее число, слова «вчера» и «позавчера» меняют дату. Если категория определилась неверно — нажмите на неё и выберите нужную: приложение запомнит.
- **Редактирование** — нажмите на любую операцию. **Удаление** — значок корзины, с подтверждением и возможностью отмены.
- **CSV для Excel** открывается двойным щелчком: разделитель «;», десятичная запятая, кириллица в UTF-8.
- **Начальный остаток** в настройках — сколько денег было до начала учёта, чтобы общий баланс совпадал с реальным.
